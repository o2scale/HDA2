# Test Design: Story 1.0 - Vertex AI Project Setup

## Test Strategy
Configuration and integration testing focused on security, connectivity, and cost controls.

## Test Scenarios

### Category: Account Setup Validation

#### TEST-1.0.1: GCP Project Creation
**Given** a GCP account with billing enabled
**When** creating a new project for the translation platform
**Then** the project should be created with:
- Meaningful name containing "translation-platform"
- Unique project ID documented
- Billing account properly linked
- Cost allocation labels applied

#### TEST-1.0.2: Spending Limits Configuration
**Given** a GCP project with billing configured
**When** setting up budget alerts
**Then** the system should:
- Alert at $500 monthly spend
- Hard cap at $1000 monthly spend
- Send notifications to designated emails
- Show alerts in GCP Console dashboard

### Category: API Enablement

#### TEST-1.0.3: Required APIs Activation
**Given** a GCP project
**When** enabling required APIs via Console or gcloud
**Then** the following APIs should be enabled:
- Vertex AI API (aiplatform.googleapis.com)
- Cloud Resource Manager API
- IAM Service Account Credentials API
- Cloud Billing API
**And** status should show "Enabled" in Console

#### TEST-1.0.4: API Availability Verification
**Given** APIs are enabled
**When** making test API calls
**Then** each API should:
- Respond without authentication errors
- Return appropriate service responses
- Show in API usage metrics

### Category: Service Account Security

#### TEST-1.0.5: Service Account Creation
**Given** appropriate IAM permissions
**When** creating the vertex-ai-translator service account
**Then** the account should:
- Have descriptive name "vertex-ai-translator"
- Be assigned exactly these roles:
  - roles/aiplatform.user
  - roles/aiplatform.serviceAgent
  - roles/storage.objectViewer
- No additional permissions beyond requirements

#### TEST-1.0.6: Credential Key Generation
**Given** a service account exists
**When** generating JSON credentials
**Then** the system should:
- Create valid JSON key file
- Download securely over HTTPS
- Prompt for secure storage location
- Not auto-save to Downloads folder

### Category: Environment Configuration

#### TEST-1.0.7: Environment File Setup
**Given** service account credentials exist
**When** configuring environment variables
**Then** the .env.example should contain:
- All required variable names
- Placeholder values with clear descriptions
- Comments explaining each variable
- Token limit references

#### TEST-1.0.8: Gitignore Verification
**Given** credentials and environment files exist
**When** checking .gitignore
**Then** the following must be excluded:
- *.json (or specifically vertex-ai-credentials.json)
- .env
- Any file containing "credentials" or "secret"

### Category: Connectivity Testing

#### TEST-1.0.9: Basic Connection Test
**Given** credentials and environment are configured
**When** running the test_vertex_ai.py script
**Then** the script should:
- Successfully authenticate with GCP
- Initialize Vertex AI client
- Send test prompt to Gemini 2.5 Pro
- Receive and display response
- Complete within 30 seconds

#### TEST-1.0.10: Error Handling Verification
**Given** the test script
**When** testing with invalid configurations
**Then** appropriate errors should be shown for:
- Missing credentials file
- Invalid project ID
- Wrong region/location
- Insufficient permissions
- Network connectivity issues

### Category: Docker Integration

#### TEST-1.0.11: Container Credential Access
**Given** Docker environment from Alex's setup
**When** mounting credentials in container
**Then** the containerized app should:
- Access credentials via volume mount
- Use environment variables correctly
- Maintain secure file permissions (600)
- Not include credentials in image

#### TEST-1.0.12: Multi-Environment Support
**Given** credentials for dev and prod
**When** switching between environments
**Then** the system should:
- Use correct credentials per environment
- Prevent dev credentials in prod
- Log which environment is active
- Fail safely if wrong credentials used

### Category: Cost Management

#### TEST-1.0.13: Token Usage Tracking
**Given** Vertex AI is configured
**When** making API calls
**Then** the system should:
- Log input token count
- Log output token count
- Calculate estimated cost
- Warn when approaching limits

#### TEST-1.0.14: Budget Alert Testing
**Given** budget alerts are configured
**When** usage approaches limits
**Then** alerts should:
- Trigger at 50% of budget ($250)
- Escalate at 80% of budget ($400)
- Send emails to stakeholders
- Appear in GCP Console

### Category: Security Validation

#### TEST-1.0.15: Credential Rotation Capability
**Given** existing service account key
**When** rotating credentials quarterly
**Then** the process should:
- Generate new key without service interruption
- Allow grace period for old key
- Update all dependent systems
- Revoke old key after confirmation

#### TEST-1.0.16: Audit Logging Verification
**Given** Vertex AI is configured
**When** making API calls
**Then** Cloud Audit Logs should record:
- All API calls with timestamps
- Caller identity (service account)
- Request/response metadata
- Any permission denied events

### Category: Documentation Testing

#### TEST-1.0.17: Setup Guide Validation
**Given** a new developer
**When** following the setup documentation
**Then** they should successfully:
- Complete setup in under 4 hours
- Configure all components correctly
- Run test script successfully
- Understand troubleshooting steps

#### TEST-1.0.18: Troubleshooting Guide
**Given** common error scenarios
**When** consulting troubleshooting guide
**Then** solutions should exist for:
- Authentication errors (401, 403)
- Quota exceeded errors (429)
- Region availability issues
- Network/firewall problems
- Token limit errors

## Test Execution Priority

- TEST-1.0.6: Credential security
- TEST-1.0.8: Gitignore verification
- TEST-1.0.9: Basic connectivity
- TEST-1.0.13: Cost tracking

### P1 - High (Should Pass)
- TEST-1.0.1: Project creation
- TEST-1.0.3: API enablement
- TEST-1.0.5: Service account setup
- TEST-1.0.11: Docker integration

### P2 - Medium (Good to Pass)
- TEST-1.0.2: Budget alerts
- TEST-1.0.14: Alert testing
- TEST-1.0.16: Audit logging
- TEST-1.0.17: Documentation

- P1 tests pass: >= 90%
- P2 tests pass: >= 80%
- No security vulnerabilities detected
- Setup time < 4 hours
- Zero credential exposures
- Costs within budget ±20%
