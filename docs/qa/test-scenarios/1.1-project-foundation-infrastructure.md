# Test Design: Story 1.1 - Project Foundation & Infrastructure

## Test Strategy
Integration testing focused on verifying all infrastructure components work together, with emphasis on Alex's Docker setup compatibility.

## Test Scenarios

### Category: Monorepo Structure

#### TEST-1.1.1: Directory Structure Validation
**Given** an empty project directory
**When** initializing the monorepo structure
**Then** the following directories should exist:
- /frontend (React application)
- /backend (FastAPI application)
- /shared (shared types)
- /infrastructure (Docker/IaC files)
- /scripts (utility scripts)
- /.github (CI/CD workflows)

#### TEST-1.1.2: Workspace Configuration
**Given** a monorepo structure
**When** checking package.json at root
**Then** it should:
- Define workspaces for frontend
- Include scripts for all services
- Support concurrent command execution
- Have proper npm/yarn workspace config

### Category: Backend Foundation

#### TEST-1.1.3: FastAPI Application Initialization
**Given** the /backend directory
**When** running the FastAPI application
**Then** it should:
- Start on port 8000
- Have entrypoint at api.main:app (for Alex's Docker)
- Load without import errors
- Support hot reload in development

#### TEST-1.1.4: Health Check Endpoint
**Given** FastAPI is running
**When** calling GET /api/health
**Then** it should:
- Return HTTP 200 OK
- Include response body with status: "healthy"
- Respond within 100ms
- Work from both localhost and Docker container

#### TEST-1.1.5: Python Dependencies Installation
**Given** requirements.txt with specified versions
**When** installing in fresh environment
**Then**:
- All packages install without conflicts
- FastAPI version is exactly 0.117.1
- Python 3.13.7 compatibility confirmed
- No security vulnerabilities in dependencies

### Category: Frontend Foundation

#### TEST-1.1.6: React Vite Initialization
**Given** the /frontend directory
**When** starting the development server
**Then** it should:
- Run on port 5173 (matching Docker config)
- Support TypeScript with strict mode
- Hot Module Replacement working
- Build without errors

#### TEST-1.1.7: Tailwind CSS Configuration
**Given** React app with Tailwind
**When** using Tailwind classes
**Then**:
- Styles apply correctly
- Purge/tree-shaking works in production
- Custom theme configurations load
- Version is exactly 3.4.13

#### TEST-1.1.8: shadcn/ui Component Setup
**Given** shadcn/ui is installed
**When** importing a component
**Then**:
- Component renders without errors
- Theme variables apply correctly
- TypeScript types are available
- Accessibility features work

### Category: Docker Integration (Alex's Setup)

#### TEST-1.1.9: Docker Compose Services Start
**Given** Alex's docker-compose.yml
**When** running `docker-compose up`
**Then** all services should start:
- PostgreSQL on port 5432
- Redis on port 6379
- Backend API on port 8000
- Frontend on port 80
- Celery worker running
- Flower on port 5555

#### TEST-1.1.10: Application-Docker Compatibility
**Given** new FastAPI and React apps
**When** running in Docker containers
**Then**:
- Backend finds api.main:app entrypoint
- Frontend builds match Nginx config
- Volume mounts enable hot reload
- Health checks pass

#### TEST-1.1.11: Environment Variables in Docker
**Given** .env.example file
**When** creating .env and starting Docker
**Then**:
- All required variables are defined
- Services read variables correctly
- No hardcoded values in code
- Secrets not exposed in logs

### Category: CI/CD Pipeline

#### TEST-1.1.12: GitHub Actions Python Jobs
**Given** .github/workflows/ci.yml
**When** pushing Python code changes
**Then** the pipeline should:
- Run Black formatting check
- Run Ruff linting
- Run mypy type checking
- Execute pytest tests
- Complete in < 3 minutes

#### TEST-1.1.13: GitHub Actions JavaScript Jobs
**Given** CI pipeline configuration
**When** pushing JavaScript/TypeScript changes
**Then** the pipeline should:
- Run ESLint checks
- Run Prettier formatting
- Execute Vitest tests
- Build production bundle
- Complete in < 3 minutes

#### TEST-1.1.14: Dependency Caching
**Given** CI pipeline with caching
**When** running successive builds
**Then**:
- Python dependencies cached
- Node modules cached
- Docker layers cached
- Second run 50% faster

### Category: Cloud Services Setup

#### TEST-1.1.15: Supabase Project Configuration
**Given** Supabase project created
**When** configuring for the application
**Then**:
- Database accessible via connection string
- pgvector extension enabled
- Auth endpoints working
- Storage buckets created
- Realtime WebSocket connects

#### TEST-1.1.16: Vercel Frontend Deployment
**Given** Vercel project configured
**When** pushing to main branch
**Then**:
- Frontend builds successfully
- Environment variables injected
- Preview URLs generated
- Production deploy works
- Custom domain configurable

#### TEST-1.1.17: Railway/Render Backend Deployment
**Given** Railway or Render configured
**When** deploying backend
**Then**:
- FastAPI starts correctly
- Health check passes
- Database connects
- Redis connects
- Logs accessible

### Category: Development Environment

#### TEST-1.1.18: Local Development Setup
**Given** fresh development machine
**When** following setup documentation
**Then** developer can:
- Clone repository
- Install dependencies
- Copy .env.example to .env
- Start all services
- Access all endpoints
- Complete in < 1 hour

#### TEST-1.1.19: Cross-Platform Compatibility
**Given** the development setup
**When** running on different OS
**Then** it should work on:
- macOS (Intel and Apple Silicon)
- Linux (Ubuntu 20.04+)
- Windows (with WSL2)

- Path separators handled

### Category: Security & Quality

#### TEST-1.1.20: Secret Management
**Given** sensitive configuration
**When** checking repository
**Then**:
- No secrets in codebase
- .gitignore blocks all sensitive files
- CI/CD uses GitHub Secrets
- Local dev uses .env file
- No credentials in Docker images

#### TEST-1.1.21: Linting and Formatting
**Given** linting configurations
**When** running checks
**Then**:
- Python: Black and Ruff pass
- JavaScript: ESLint passes
- TypeScript: Strict mode no errors
- Pre-commit hooks work
- CI/CD enforces standards

#### TEST-1.1.22: Testing Infrastructure
**Given** test configurations
**When** running test suites
**Then**:
- pytest runs backend tests
- Vitest runs frontend tests
- Coverage reports generated
- Tests run in CI/CD
- Fixtures work properly
