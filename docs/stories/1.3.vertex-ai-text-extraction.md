# Story 1.3: Vertex AI Text Extraction Integration

## Status
Draft

## Story
**As a** User,
**I want** to extract text from uploaded PDFs and images using AI,
**so that** I can access and edit the content for translation.

## Acceptance Criteria
1. Vertex AI Gemini 2.5 Pro integration for text extraction (not standard Gemini API)
2. Support for both printed and handwritten text extraction
3. Preserve document structure (indentation, line breaks, formatting)
4. Handle mixed-language source documents
5. Process documents in batches of 10-100 pages based on token limits
6. Real-time progress updates during extraction
7. >95% accuracy for printed text, >85% for handwritten content
8. Fallback to AWS Textract if Vertex AI fails

### Batch Processing Strategy
- Calculate tokens: ~500 tokens per page
- Max batch: 200K input tokens (400 pages theoretical)
- Practical limit: 100 pages per batch for safety
- Queue batches with Celery for parallel processing
- Use Redis to track job progress

### Error Handling
- Token limit exceeded: Split batch and retry
- API timeout: Exponential backoff with max 3 retries
- Malformed response: Fall back to AWS Textract
- Low confidence: Flag for manual review
- Service unavailable: Queue for later processing

### Performance Requirements
From [Source: prd/overview-requirements.md#NFR1]:
- >95% accuracy for printed text
- >85% accuracy for handwritten content
- 100% accuracy for Sanskrit/religious terminology
- Processing time: 30-60s per page acceptable
- Structure preservation is critical for religious texts
